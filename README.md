# sprinter-mkdll

`sprinter-mkdll` — кроссплатформенный инструмент создания, проверки и
конвертации динамических библиотек для Sprinter libman. Он заменяет старый
DOS/Windows `MK_DLL.EXE`, сохраняя его двухпроходный способ построения
relocation bitmap.

Нужен Python 3.10+ и внешний Z80-ассемблер. Сам пакет не включает ассемблер.

```sh
python -m pip install .
sprinter-mkdll build library.asm --format l1 --assembler sjasmplus -o library.dll
sprinter-mkdll verify library.dll --target 1.3
sprinter-mkdll inspect library.dll
```

## Совместимость

| Целевой менеджер | Поддерживаемый формат |
| --- | --- |
| libman 1.2 | L0 |
| libman 1.3 (в `FILE_ID.DIZ` также назван 1.13) | L0, L1 |

Для программ, которые загружают и вызывают DLL, используйте актуальный
подключаемый менеджер [`libman/libman.asm`](libman/libman.asm). В отличие от
исторической версии он разрешает простое имя DLL относительно каталога
запущенного EXE и только затем откатывается к текущему каталогу.

Для программ с архитектурой, занимающей WIN0, загрузчик можно разместить в WIN0:
[`libman/libman_core.inc`](libman/libman_core.inc) содержит только временно
исполняемый код загрузки, а
[`libman/libman_state.inc`](libman/libman_state.inc) — публичный API, вызов и
выгрузку DLL, таблицу и состояние для постоянно отображаемого WIN1. В этом
режиме DLL размещаются в WIN2 или WIN3; подробный контракт и настройки
буферов описаны в [`libman/README.md`](libman/README.md).

Для проверки менеджера на Sprinter/MAME используйте
[`examples/libmantst`](examples/libmantst): тестовое приложение последовательно
загружает тестовые L0/L1 и исторические `ANTONFNT.DLL`/`TEST.DLL` из `docs`,
проверяет `l_info`, регистры вызова и `l_free`.

По умолчанию `build` создаёт L1 для libman 1.3. Для старого исходника,
предназначенного для исторического `mk_dll`, указывайте `--format l0 --target
1.2`.

```sh
sprinter-mkdll build docs/libman/LIB.A --format l0 --target 1.2 --assembler zmac
```

## Форматы L0 и L1

Оба формата имеют 32-байтный little-endian заголовок:

| Offset | Size | Field |
| ---: | ---: | --- |
| `00h` | 2 | signature: `L0` или `L1` |
| `02h` | 2 | размер загружаемого prefix; сжатого, если RLE включён |
| `04h` | 2 | размер несжатого образа до relocation table |
| `06h` | 2 | размер relocation bitmap |
| `08h` | 2 | сумма несжатых байтов начиная с `10h`, по модулю 65536 |
| `0Ah` | 1 | день |
| `0Bh` | 1 | месяц |
| `0Ch` | 2 | год |
| `0Eh` | 2 | версия: `major << 8 | minor` |
| `10h` | 16 | NUL-terminated описание библиотеки |

Физический DLL может содержать дополнительные данные после загружаемого
prefix. Они не входят в checksum и доступны библиотеке через file handle,
передаваемый в `init`. Команды анализа и конвертации сохраняют этот trailing
payload без изменений.

В L0 заголовок является частью ассемблируемого образа. Размер образа округляется
до 256 байт, а bitmap описывает весь образ; первые четыре bitmap-байта должны
быть нулевыми, чтобы не релокировать заголовок. В L1 заголовок создаётся
инструментом, код начинается с `20h`, а bitmap описывает только код после
заголовка. Эта разница соответствует загрузчику `LIBMAN13.ASM`.

Полный несжатый образ `code + relocation table` и загружаемый prefix должны
помещаться в 16 KiB.

При сжатии первые 16 байт пишутся как есть. Далее ненулевые байты пишутся
буквально, а последовательность нулей кодируется парой `00 count`; `count=0`
означает 256 нулей. Если RLE не уменьшает размер, инструмент записывает
несжатую форму: равенство размеров загрузчик не умеет отличить от несжатого
файла.

## Сборка

Инструмент создаёт две временные копии исходника и запускает ассемблер с двумя
виртуальными базами, отличающимися на `0x100`. Для L0 используются `0x0000` и
`0x0100`; для L1 — `0x0020` и `0x0120`, потому что код расположен после
32-байтного заголовка. Изменившиеся старшие байты адресов отмечаются в bitmap.
Исходный файл и его каталог не меняются.

Поддерживаются профили:

- `zmac` — исторический вызов `zmac source.asm`, синтаксис `ORG #0000`;
- `z80asm` — `z80asm -b -ooutput.bin source.asm`, синтаксис `ORG 0x0000`;
- `sjasmplus` — `sjasmplus --raw=output.bin source.asm`, синтаксис `ORG 0x0000`;
- произвольный вызов через `--assembler-command`. Шаблон обязан содержать
  `{source}` и может использовать `{output}`, `{source_dir}` и `{include_path}`.

Для встроенных профилей каталог исходника автоматически добавляется в include
path. Дополнительные каталоги задаются повторяемым `-I/--include-dir`. В
пользовательском command template include options указываются непосредственно
в шаблоне, например `-I {source_dir}`.

Для L1 имя, версия и дата задаются флагами `--name`, `--version 1.2`,
`--date 2003-07-15`. По умолчанию используются имя исходного файла, версия
`1.0` и текущая дата. У L0 эти флаги переопределяют значения старого заголовка
в ASM. Поле имени ограничено 15 байтами; доступны `--encoding ascii` и
`--encoding cp866`.

## Дополнительные команды

```sh
# Полная проверка signature, размеров, RLE, checksum и bitmap.
sprinter-mkdll verify LIB.DLL --target 1.3

# Метаданные в человекочитаемом или JSON-виде.
sprinter-mkdll inspect LIB.DLL --json

# Каноническая несжатая форма.
sprinter-mkdll decompress LIB.DLL -o LIB.raw.dll

# Конвертация сохраняет код и меняет схему bitmap.
sprinter-mkdll convert old.dll -o new.dll --format l1
sprinter-mkdll convert new.dll -o old.dll --format l0 --no-compress
```

`convert` между L0 и L1 сохраняет общий образ: добавляет либо удаляет четыре
нулевых bitmap-байта, относящихся к 32-байтному заголовку, после чего
пересчитывает размеры и checksum. Trailing payload сохраняется.

При создании L1 инструмент также обходит ошибку libman 1.3: ненулевой размер
relocation table не должен иметь одинаковые старший и младший байты (`0101h`,
`0202h` и т. п.). При необходимости в конец кода добавляется до восьми нулевых
байтов; `verify` отклоняет внешние DLL с опасным размером таблицы.

## Standalone-бинарники

Для локального standalone-исполняемого файла:

```sh
python -m pip install '.[standalone]'
python scripts/build_standalone.py
```

GitHub Actions workflow собирает архивы для macOS, Linux и Windows. В них
содержится только `sprinter-mkdll`; выбранный Z80-ассемблер устанавливается
отдельно.
