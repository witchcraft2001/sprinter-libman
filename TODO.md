## Полный ABI вызова DLL

На будущее добавить расширенный вызов DLL, не меняя семантику существующего
`l_call`.

Предлагаемая архитектура:

- общий внутренний full-call engine;
- `l_call_full_raw` для ASM: передача и возврат `AF`, `BC`, `DE`, `HL`,
  `IX`, `IY` и альтернативных регистров непосредственно через Z80-регистры;
- ASM-макрос с адресом единственной переменной, содержащей динамический
  handle, и номером функции в inline-данных после `CALL`;
- `l_call_full_ctx` для C/Pascal: handle, функция и полный образ регистров
  передаются через версионированную структуру;
- отдельный статус менеджера, чтобы отличать ошибку диспетчеризации от
  флагов, возвращённых DLL;
- старые `l_load`, `l_call`, `l_info`, `l_free` и ABI существующих DLL
  оставить без изменений.

Для SDCC Sprinter SDK:

- добавить `libman.h` со структурой `libman_regs_t`;
- реализовать ASM-обёртку, учитывающую ABI SDCC 2.9.0 и сохраняющую
  принадлежащие компилятору регистры;
- поверх универсальной структуры предусмотреть типизированные обёртки для
  конкретных DLL.

Для tpascal:

- расширить `dss_pascal_src/lib_pas/LIBMAN.INC`;
- добавить запись наподобие `LibFullRegs` и функцию
  `LibCallFull(handle, func, var regs)`;
- реализовать вызов через Pascal-процедуру с внутренним `asm ... end`, как
  текущий `LibAsmCall`, не полагаясь на нестабильный ABI параметризованных
  `external`-процедур;
- сохранять IX/IY и прочее состояние, которым владеет Pascal runtime.

Дополнительно рассмотреть документированный parameter-block ABI для новых
функций DLL. Он позволит предоставлять типизированные C/Pascal API без
прямой работы пользователей с Z80-регистрами.

Открытые вопросы перед реализацией:

- точный бинарный layout и версионирование структуры контекста;
- какие флаги и альтернативные регистры гарантированно возвращаются;
- размещение контекста относительно переключаемого окна;
- поведение при вложенных вызовах и прерываниях;
- оценка размера runtime-части в WIN1;
- нужны ли binding slots как дополнительный вариант для overlay и полностью
  ручной сборки.
